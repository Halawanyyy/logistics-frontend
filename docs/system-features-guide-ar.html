1) نظرة عامة ومعمارية النظام

النظام منصة ERP تشغيلية لشركة شحن وFulfillment: يستقبل الطلب، يسعّر الشحن، يدير المخزون وتجهيز الطلب، ينشئ الشحنة ويوزعها على السائق، ثم يسجل التحصيلات والمصروفات ومستحقات التاجر.

بوابة الإدارة الداخلية

Front واجهة لموظفي الإدارة، التشغيل، المخزن والمالية، والقوائم الظاهرة تتغير حسب صلاحيات المستخدم.

Back APIs محمية بـSanctum وصلاحيات دقيقة لكل عملية عرض أو إنشاء أو تعديل أو اعتماد.

بوابة التاجر

Front مساحة مستقلة للتاجر لمتابعة طلباته وشحناته ومخزونه وأمواله وفريقه.

Back يعزل بيانات كل تاجر تلقائيًا ويحدد ما يراه حسب دوره داخل حساب التاجر.

التتبع العام للعميل

Front + Back صفحة عامة للبحث برقم الشحنة وعرض الحالة والخط الزمني الآمن، من غير كشف بيانات العميل أو السائق أو المعلومات المالية الداخلية.

تكاملات المتاجر الإلكترونية

Front + Back إنشاء Tokens للتكامل، عرض دليل الاستخدام، اختبار الاتصال، ثم استقبال طلبات من WooCommerce أو Shopify أو أي نظام خارجي.

الـBackend غير موجود ككود تنفيذي داخل مجلد الـFrontend الحالي؛ لذلك تم توثيقه من عقود الاستدعاء وتقارير الـBackend الموجودة في docs/. أي تفصيل خلفي في هذا التقرير يعكس العقود والتقارير المتاحة بتاريخ الإصدار.

2) الخصائص العامة للواجهة الأمامية

واجهة عربية وإنجليزية

Front تبديل فوري بين العربية والإنجليزية مع تحويل اتجاه الصفحة RTL/LTR وحفظ اللغة المختارة محليًا.

Back إرسال X-Locale وAccept-Language للحصول على رسائل وStatus Labels مترجمة.

الوضع الفاتح والداكن

Front دعم Light/Dark Theme، واحترام إعداد الجهاز عند أول استخدام، ثم حفظ تفضيل المستخدم.

قوائم ديناميكية بالصلاحيات

Front إخفاء الصفحات والأزرار غير المسموح بها، وحماية المسارات بشاشات 401/403/404.

بحث عام في لوحة الإدارة

Front البحث في الطلبات والشحنات والتجار والسائقين ومنتجات المخزن، ولا يبحث المستخدم إلا في الموارد التي يملك صلاحيتها.

قوائم وفلاتر موحّدة

Front جداول، Pagination، بحث، فلاتر حالة وتاريخ وتاجر وسائق ومخزن، مع حالات تحميل وفراغ وخطأ موحّدة.

نماذج آمنة وسهلة

Front React Hook Form وZod للتحقق قبل الإرسال، وإظهار أخطاء الـAPI بجانب الحقول، ونوافذ تأكيد للعمليات الحساسة.

إدارة البيانات والكاش

Front React Query لجلب البيانات وإعادة التحميل والكاش، وZustand للاحتفاظ بالجلسة.

الطباعة والتنزيل

Front + Back معاينة وطباعة Labels وWaybills وManifests وتنزيل PDF/CSV والملفات المرفقة.

3) الدخول والأمان والصلاحيات

تسجيل الدخول والخروج

Front شاشة دخول، حفظ الجلسة، تحميل المستخدم الحالي، والخروج مع تنظيف الجلسة حتى لو انتهى الـToken.

Back Bearer Token عبر Laravel Sanctum، مع Throttling لمحاولات الدخول.

معالجة 401 و403 تلقائيًا

Front أي رد 401 ينهي الجلسة ويعيد المستخدم لصفحة الدخول الصحيحة؛ و403 ينقله لصفحة منع الوصول.

RBAC للإدارة

Front + Back 164 مفتاح صلاحية تغطي العرض والإنشاء والتعديل والحذف والاعتماد والطباعة والعمليات المالية والمخزنية.

Capabilities للتاجر

Front + Back الصلاحيات تأتي من /merchant-portal/me وتتحكم في الـSidebar والصفحات والأزرار والـWidgets.

عزل بيانات التجار

Back هوية التاجر تؤخذ من العضوية أو Integration Token؛ إرسال merchant_id من بوابة التاجر مرفوض، ومحاولة فتح مورد لتاجر آخر تُرجع 404.

حماية الملفات والبيانات الحساسة

Back تنزيل الملفات من Controllers محمية، إخفاء مسارات التخزين، رفض Path Traversal، وإرجاع Token التكامل الخام مرة واحدة فقط عند الإنشاء.

4) لوحة تحكم الإدارة

ملخص التشغيل

Front Cards ورسوم بيانية لإجمالي الشحنات، انتظار الاستلام، قيد النقل، خرجت للتسليم، تم التسليم، والفشل والمرتجعات.

الملخص المالي

Front + Back أرباح الشركة، COD المحصّل، مستحقات التجار، التسويات، المصروفات والمدفوعات ضمن الفلاتر المتاحة.

فلاتر الإدارة

Front + Back تحليل حسب فترة زمنية، تاجر، أو سائق، مع إعادة حساب الـKPIs من الـBackend.

رسوم تحليلية

Front Recharts لعرض حالات الشحنات والاتجاه المالي بدل الاعتماد على أرقام منفصلة فقط.

5) المستخدمون والأدوار والإعدادات

المستخدمون الداخليون

Front + Back عرض وإنشاء وتعديل وحذف Soft Delete للمستخدمين، وربط كل مستخدم بدور وظيفي.

الأدوار المخصصة

Front + Back إنشاء دور، تعديله، عرض تفاصيله، حذف الأدوار غير المحمية، ومزامنة صلاحياته.

الصلاحيات مجمعة حسب الوحدة

Front Multi-select/checkbox groups تجعل تعيين صلاحيات المخزن والمالية والطلبات وغيرها واضحًا وقابلًا للمراجعة.

إعدادات النظام

Front + Back عرض الإعدادات حسب مجموعات، تعديل عنصر واحد أو Bulk Update، ودعم إعدادات عامة للهوية والشحن والمخزن والطباعة والمالية.

الهوية البصرية وبيانات الشركة

Front + Back تحميل اسم الشركة والشعار وبيانات التواصل من الإعدادات العامة واستخدامها في واجهة النظام والمستندات القابلة للطباعة.

6) إدارة التجار وبيانات المتجر

ملفات التجار

Front + Back قائمة التجار، إنشاء وتعديل وحذف، وحفظ بيانات الشركة والتواصل والعنوان والحالة.

صفحة تاجر شاملة

Front Tabs/لوحات لملخص التاجر، Dashboard، المالية، المخزون، الحركات والرسوم.

محفظة التاجر من الإدارة

Front + Back عرض الرصيد والحركات، تسجيل إيداع أو سحب، واعتماد أو رفض الحركة حسب الصلاحية.

مستخدمو بوابة التاجر

Front + Back إنشاء وتعديل وحذف مستخدمي التاجر، وتفعيلهم أو إيقافهم وتحديد دور كل شخص.

Integration Tokens

Front + Back عرض وإنشاء ومراجعة وإلغاء وحذف مفاتيح التكامل الخاصة بكل تاجر.

كتالوج الشركة ومعاينة المتجر

Front + Back إدارة عناصر كتالوج الشركة، ومعاينة شكل متجر التاجر والمنتجات والبيانات المتاحة للعرض.

7) المحافظات والمناطق والتسعير

المحافظات والمناطق

Front + Back CRUD كامل للمحافظات والمناطق، مع ربط المنطقة بمحافظتها واستخدامها في عناوين الطلبات.

أسعار الشحن

Front + Back إنشاء وتعديل وتعطيل الأسعار، مع Restore وForce Delete للسجلات المحذوفة عند الحاجة.

حاسبة سعر الشحن

Front + Back اختيار الموقع والخطة والمدخلات المطلوبة والحصول على السعر المحسوب قبل إنشاء الطلب.

خطط التسعير

Front + Back خطط منفصلة لكل شريحة/تاجر، مع أسعار تفصيلية لكل منطقة وإدارة دورة حياة الخطة.

8) الطلبات

قائمة الطلبات وتفاصيلها

Front بحث وفلاتر وحالات، مع صفحة تفاصيل تجمع العميل والعنوان والأصناف والدفع والشحن والمخزن.

إنشاء وتعديل الطلب

Front + Back بيانات المستلم والعنوان والأصناف والكميات ونوع الدفع وFulfillment والتغليف والتكلفة.

تأكيد وإلغاء الطلب

Front + Back انتقالات حالة مقيدة بقواعد العمل؛ لا يُسمح بإجراءات تناقض مرحلة الطلب الحالية.

الحجز من المخزون

Back حجز الكميات للطلب، تحرير الحجز، أو Fulfillment كامل من المخزن مع حماية من السحب الزائد.

دورة تجهيز الطلب

Front + Back بدء Picking، تأكيد السحب، بدء Packing، تأكيد التغليف، ثم Ready for Dispatch.

طباعة Label الطلب

Front + Back معاينة أو تنزيل/طباعة مستند الطلب بصيغ HTML أو PDF أو أوامر طابعة حرارية حسب الإعداد.

9) الشحنات والتسليم

إنشاء شحنة من الطلب

Front + Back تحويل الطلب المؤهل إلى شحنة تحمل رقم تتبع وحالة تشغيلية ومبلغ COD وبيانات العنوان.

تغيير حالة الشحنة

Front + Back حالات مثل انتظار الاستلام، قيد النقل، خرجت للتسليم، تم التسليم، فشل، أو مرتجع، مع سجل زمني.

تعيين السائق

Front + Back ربط الشحنة بسائق مؤهل، وإظهار المشحون وغير المعيّن لدعم التخطيط اليومي.

محاولات التسليم

Front + Back تسجيل كل محاولة ونتيجتها وملاحظاتها، وإتمام التسليم مع قيمة التحصيل الفعلية عند الحاجة.

التتبع الزمني

Front Timeline واضح داخل الإدارة وبوابة التاجر وصفحة العميل العامة، مع مستوى بيانات مناسب لكل جمهور.

Labels وWaybills والطباعة المجمعة

Front + Back طباعة ملصق شحنة، بوليصة، قائمة طباعة، أو مجموعة ملصقات لتسريع التشغيل.

10) السائقون وDriver Manifests

إدارة السائقين

Front + Back بيانات السائق والهاتف والمركبة واللوحة والحالة، مع إنشاء وتعديل وحذف وعرض التفاصيل.

شحنات السائق

Front + Back عرض الشحنات المسندة لكل سائق وحالتها لتسهيل المتابعة اليومية.

خطة/كشف التوزيع اليومي

Front + Back توليد Manifest يجمع شحنات السائق، مراجعة التفاصيل، الطباعة، ثم الإغلاق بعد انتهاء الوردية.

نقدية السائق والتسوية

Front + Back حساب النقدية المتوقعة من COD، تسجيل Cash Closure، وإظهار أي فروق للمراجعة المالية.

11) المخازن والكتالوج والمخزون

المستودعات

Front + Back إنشاء وتعديل وعرض وحذف المستودعات وبياناتها الأساسية.

منتجات المخزن

Front + Back تعريف المنتج والتاجر وSKU وBarcode وحد التنبيه والحالة، مع صفحات قائمة وتفاصيل ونماذج.

أرصدة المخزون

Front + Back المتاح والمحجوز والتالف والإجمالي لكل منتج ومكان، مع تعديل يدوي Audit-friendly.

تنبيهات Low Stock

Front + Back قوائم وكروت سريعة للمنتجات التي وصلت لنقطة إعادة الطلب.

حركات المخزون

Front + Back سجل لكل دخول وخروج وحجز وإفراج وتحويل ومرتجع وتلف وتسوية، مع مرجع العملية ووقتها.

حجوزات المخزون

Front + Back ربط الكمية المحجوزة بالطلب لمنع بيع نفس الرصيد أكثر من مرة.

المناطق والرفوف والخانات

Front + Back تقسيم المستودع إلى Zones ثم Shelves ثم Bins لتحديد موقع الصنف بدقة، مع Label لكل خانة.

Warehouse Receipts

Front + Back إنشاء إذن استلام، إدخال الأصناف والكميات، التعديل قبل التأكيد، ثم Confirm لزيادة الرصيد أو Cancel.

التحويل بين المخازن

Front + Back إنشاء Transfer ثم Confirm وDispatch وReceive أو Cancel، مع تتبع حالة وكميات التحويل.

طلبات توريد التاجر

Front + Back التاجر يرسل إشعار وصول متوقع؛ الإدارة توافق أو ترفض وتربطه بإذن استلام فعلي.

12) السحب والتغليف والمرتجعات ورسوم المخزن

Picking Lists

Front + Back توليد قائمة سحب للطلب، إرشاد العامل للأصناف ومواقعها، دعم Scan بالباركود، ثم الإلغاء عند الحاجة.

Packing Tasks

Front + Back توليد مهمة تغليف بعد السحب، عرض الأصناف المطلوبة، ثم إكمال المهمة لتجهيز الطلب للشحن.

المرتجعات

Front + Back إنشاء المرتجع، استلامه، فحصه، إعادة الصالح للمخزون أو تسجيل التالف، رفضه أو إغلاقه.

قواعد رسوم التخزين

Front + Back تعريف قواعد التخزين وتوليد الرسوم على التجار وفق الفترة والاستهلاك.

قواعد Pick & Pack

Front + Back تحديد تكلفة السحب والتغليف وتوليد الرسوم المرتبطة بعمليات التجهيز.

Warehouse KPIs

Front + Back مؤشرات الأداء للمخزون والاستلام والتحويل والسحب والتغليف والرسوم خلال فترة محددة.

13) المالية والخزينة

التقارير المالية

Front + Back Overview، Daily Cash، Merchant Ledger، فروق السائقين، إيراد المخزن، والأرباح والخسائر.

مدفوعات التجار

Front + Back إنشاء طلب Payout وتعديله، ثم اعتماد أو رفض أو إكمال الصرف مع سجل الحالة.

المصروفات

Front + Back CRUD للمصروفات، واعتماد/رفض المصروف ثم تعليمه كمدفوع وربطه بحساب خزينة عند الحاجة.

إغلاقات نقدية السائقين

Front + Back مطابقة COD المتوقع مع المستلم فعليًا وحفظ الفروق كجزء من التسوية.

فواتير التجار

Front + Back إنشاء وتعديل وعرض الفاتورة، Preview، وتنزيل PDF، مع عزل ملفات كل تاجر.

حسابات الخزينة

Front + Back إدارة الحسابات النقدية/البنكية وعرض الحركات التي تؤثر على كل حساب.

محفظة التاجر

Front + Back Available/Pending Balance، دفتر حركات، إيداع وسحب واعتماد/رفض، مع Idempotency للحركات الناتجة عن مصدر واحد.

المصالحة المالية

Back ملخص تسوية يربط التحصيل والمدفوعات والمصروفات ومستحقات التجار لكشف الفروق.

14) التشغيل والطباعة والتقارير المساندة

عمليات الباركود

Front + Back Lookup لأي باركود، التعرف على منتج المخزن، أو Scan لتحديث حالة شحنة في سياق التشغيل.

نظام Labels موحّد

Front + Back منتجات وشحنات وطلبات وخانات مخزن وDriver Manifests، مع Preview وTest وإعدادات أبعاد وسرعة وكثافة الطابعة.

صيغ الطباعة

Front + Back HTML وPDF وZPL وTSPL وJSON، مع دعم طابعات Zebra وTSC والطباعة من المتصفح.

Exports

Front + Back طلب تصدير، متابعة حالته، فتح التفاصيل، ثم تنزيل الملف المكتمل، للإدارة والتاجر كلٌ في نطاقه.

المرفقات

Front + Back إرفاق مستند بطلب أو Payout أو مورد مدعوم، عرض التفاصيل والتنزيل والحذف حسب الصلاحية.

Audit Logs وTimeline

Front + Back سجل من قام بالفعل ومتى وعلى أي مورد، مع Timeline ومراجعة عمليات حساسة مثل إعدادات النظام والمدفوعات والتكاملات.

15) بوابة التاجر — الخصائص المتاحة

بوابة التاجر لا تعرض بيانات كل الشركة؛ الـBackend يحدد التاجر الحالي وصلاحيات المستخدم، ثم الواجهة تُظهر فقط الوحدات المسموحة.

Dashboard التاجر

ملخص الطلبات والشحنات، عدد المنتجات وLow Stock وطلبات التوريد، ورصيد المحفظة والفواتير والمدفوعات إذا كان للمستخدم صلاحية مالية.

الطلبات

عرض وبحث، Quick View، إنشاء وتعديل الطلبات المؤهلة، تأكيد أو إلغاء، وطباعة Label.

الشحنات

عرض الشحنات وتفاصيلها، Tracking Timeline، وتنزيل Label أو Waybill من غير إمكانية تغيير التشغيل الداخلي.

المنتجات والمخزون

عرض المنتجات وتفاصيلها، أرصدة المخزون، Low Stock، حركات المخزون، ورسوم التخزين والتجهيز.

طباعة باركود المنتجات

Label لمنتج واحد أو Bulk Labels بعدد نسخ محدد، مع اختيار الصيغة المناسبة للطابعة.

Inbound Requests

إنشاء طلب توريد، تحديد موعد الوصول والأصناف والكميات، متابعة الحالة، وإلغاء الطلب وهو ما زال Pending.

المالية

ملخص مالي، Wallet، سجل الحركات، تفاصيل الفواتير وPreview/Download، وطلب Payout ومتابعة حالته.

فريق التاجر

عرض وإنشاء وتعديل وحذف المستخدمين، وإيقاف أو إعادة تفعيل العضو، حسب دور Owner/Admin.

الملف والإعدادات

الـOwner يدير بيانات الشركة؛ والإعدادات تشمل Defaults للطلب والعنوان والطباعة وتفضيلات الإشعارات.

التكاملات

Tokens، ظهور السر مرة واحدة، Revoke/Delete، دليل API داخل الواجهة، وأداة Test للاتصال.

التصدير

اختيار نوع التقرير والفلاتر، إنشاء Export، متابعة Pending/Completed/Failed، ثم تنزيل الملف.

المرفقات والإشعارات

الـAPI وصفحات الواجهة موجودة لرفع/تنزيل المرفقات وقراءة الإشعارات وتعليمها كمقروءة.

المتجر

صفحة Store محمية بصلاحية store.view لعرض واجهة/بيانات المتجر المخصصة للتاجر.

ملاحظة تنفيذية: صفحات وإجراءات المرفقات والإشعارات موجودة في الكود، كما أنها تظهر ضمن عناصر التنقل حسب الـCapability، لكن مسارات /merchant/attachments و/merchant/notifications غير مسجلة حاليًا في Router؛ لذلك تحتاج ربط Route قبل اعتبارها متاحة للمستخدم من البداية للنهاية.

17) خصائص الـBackend الداعمة للنظام

Laravel Modular Monolith

الوحدات الخلفية مفصولة منطقيًا: Auth، Users، Merchants، Orders، Shipments، Drivers، Warehouse، Finance، Labels، Exports، Attachments، Audit وغيرها.

عقود API واسعة

الواجهة الحالية تحتوي على 364 دالة تكامل TypeScript تغطي القراءة والإنشاء والتعديل والحذف والاعتماد والتنزيل والطباعة.

التحقق من المدخلات

Form Requests وقواعد 422، منع merchant_id في مسارات التاجر والتكامل، والتحقق من انتقالات الحالات والملكية.

الأمان على مستوى المسار

المسارات الإدارية خلف auth:sanctum وPermission Middleware، وبوابة التاجر خلف Merchant Portal Middleware، والتكامل خلف Token Middleware.

التدقيق Audit

تسجيل تغييرات الإعدادات، المدفوعات، المصروفات، المرفقات، التصدير، إنشاء وإلغاء Tokens، وعمليات حساسة أخرى.

التعريب

رسائل وحقول *_label بالعربية والإنجليزية مع الحفاظ على القيم الخام ثابتة للتكاملات.

حماية Public Tracking

إرجاع حالة وخط زمني منقّح فقط، بدون الاسم الكامل أو العنوان الكامل أو ملاحظات داخلية أو بيانات مالية.

Rate Limiting

مطبق على Login والتتبع العام وIntegration API، مع توصية بإضافته مستقبلًا لتوليد الصادرات والرفع الجماعي وطلبات Payout.

الملفات الخاصة

Attachments وExports وInvoices تُحفظ خارج المسار العام وتُنزل عبر Controller يتحقق من الصلاحية والملكية والمسار.

اختبارات تدفقات العمل

التقارير تشير إلى اختبارات Auth وOrder/Shipment وWarehouse وFinance وDriver Manifest وLabels وMerchant Portal وSecurity وغيرها.

19) حالة الجاهزية والملاحظات المهمة

بناء الـFrontend

المشروع React 19 + TypeScript + Vite، ويحتوي على بنية صفحات كبيرة وتكاملات API فعلية وتصميم موحد للبوابتين.

جاهزية الـBackend

تقارير المشروع تصفه قويًا في حماية المسارات وعزل التجار وسلامة التدفقات، لكن آخر Audit ذكر أن تشغيل مجموعة اختبارات Laravel الكاملة ظل خطوة تحقق يدوية مطلوبة.

العمليات الثقيلة

الصادرات والفواتير والإشعارات تبدو متزامنة في التقرير الحالي؛ تحت ضغط مرتفع يُفضّل نقل المهام الثقيلة إلى Queue مع مراقبة الـWorkers.

التخزين والنسخ الاحتياطي

يلزم Backup لقاعدة البيانات والملفات الخاصة، وسياسة Retention للصادرات والفواتير والمرفقات لتجنب امتلاء التخزين.

الطباعة العربية

HTML هو الخيار الأكثر أمانًا للعربية. مخرجات ZPL/TSPL تعتمد على إمكانيات الطابعة والخط، وPDF الخلفي الحالي موصوف كحل نصي خفيف.

نطاق هذا المستند

الدليل يشرح المزايا التشغيلية. للتفاصيل الحرفية لكل Endpoint وPayload وResponse تُراجع ملفات docs/api-documentation.md وdocs/api-endpoints-list.md.
